세일 시작 직후 선착순 쿠폰 발급

세일이 열리자마자 요청이 한꺼번에 몰리고, 한정 수량만 발급해야 합니다. 같은 사용자가 버튼을 여러 번 누르기도 합니다. 버튼을 누르면 실제 서버가 같은 요청 묶음을 네 가지 방식으로 차례로 처리하고, 초과 발급과 요청별 대기 시간을 비교합니다.

실행하면 방식별 결과가 채워집니다.

여기서 보이는 것

락 없음: 남은 수량을 읽고 1을 빼 저장하는 사이에 다른 요청이 끼어들어, 수량보다 많이 발급됩니다.

비관적 락: 초과 발급은 없지만 모든 요청이 쿠폰 행 하나의 락을 기다립니다. 처리 시간이 락 안에 있어 요청이 몰릴수록 대기 시간이 길어집니다.

조건부 차감: UPDATE … SET remaining = remaining - 1 WHERE remaining > 0 한 문장으로 확인과 차감을 같이 합니다. 처리 시간을 락 밖에서 쓰고, 행 잠금은 이 한 문장 동안만 잡습니다.

Redis 게이트: 남은 수량 확인·차감과 사용자 중복 확인을 Lua 스크립트 하나로 Redis에서 먼저 합니다. 통과한 요청(수량만큼)만 DB 트랜잭션까지 가고, 나머지는 커넥션도 잡지 않고 바로 돌아갑니다. DB 쪽은 조건부 차감으로 한 번 더 지킵니다.

중복 발급: 모든 방식에서 (쿠폰, 사용자) 유니크 키로 막습니다. 위반하면 트랜잭션이 롤백돼 차감도 되돌아갑니다.
