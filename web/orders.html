매장 동시 주문과 재고 정합성

여러 POS에서 같은 상품 주문이 동시에 들어옵니다. 주문마다 재고 차감 → 커밋 → 외부 결제 승인 순서로 진행하고, 승인이 실패하면 보상 트랜잭션으로 재고를 되돌립니다. 버튼을 누르면 실제 서버가 DB 트랜잭션으로 주문을 동시에 처리하고, 끝난 뒤 DB 재고를 그대로 보여 줍니다.

여기서 보이는 것

락 없음: 두 주문이 같은 재고 값을 읽고 각자 1을 빼서 저장하면 차감 하나가 사라집니다(lost update). 판매는 됐는데 재고가 줄지 않아 초과 판매가 생깁니다.

비관적 락: SELECT … FOR UPDATE로 같은 상품의 차감을 줄 세웁니다. 결제 승인은 트랜잭션 밖에서 기다려 락과 커넥션을 오래 잡지 않습니다.

보상 트랜잭션: 외부 승인은 DB 트랜잭션으로 묶을 수 없어서, 실패하면 이미 커밋한 차감을 반대 연산으로 되돌립니다.

아웃박스: 발행이 실패하면 남겨 두고 다음 주기에 다시 보냅니다. 전달은 됐지만 응답을 못 받으면 같은 이벤트가 또 나가므로(at-least-once), 컨슈머가 eventId 유니크 키로 중복을 걸러냅니다.

마지막 요청

-

인메모리 H2 DB에서 실행합니다. 경합이 잘 보이도록 조회와 저장 사이에 30ms 처리 시간을 두었고, 결제 승인 지연(150–400ms)과 실패는 시드로 재현되는 모의 값입니다. 무료 서버라 한동안 요청이 없으면 첫 응답이 30초~1분 늦을 수 있습니다.
